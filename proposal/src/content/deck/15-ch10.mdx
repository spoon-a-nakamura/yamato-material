>

<h4>日々の更新は、この3手順で完結します</h4>

<Steps row>
  <Step title="一覧表を編集する">
  普段お使いの一覧表を、いつもどおりの操作で編集します。
  </Step>
  <Step title="「同期」を押す">
  管理画面に用意するボタンを押します。商品情報の入力欄はありません。
  </Step>
  <Step title="差分を確認して反映">
  追加・更新・公開停止の件数をご確認いただいたうえで反映されます。
  </Step>
</Steps>

<Cols n="2-1" class="mt-4">
  <KeyPoint>
  商品情報を入力する画面は、あえてご用意しません。<strong>正しいデータは常に貴社の一覧表の側</strong>にあり、Webカタログはその写しとなります。どちらが最新かを気にしていただく必要がなくなります。
  </KeyPoint>

  <Note>
  反映されるのはボタンを押していただいたときだけです。一覧表を編集している途中の状態が、意図せずWebに出てしまうことはありません。
  </Note>
</Cols>

</Slide>

<Slide
  chapter="10"
  chapterTitle="データ管理と運用設計"
  no="10-2"
  title="同期を安全に行うための仕組み"
  variant="center"
  lead="一覧表が唯一の正となるため、表の上の入力ミスがそのまま公開に出ることのないよう、次の仕組みを備えます。"
>

<Cols n="2-1">
  <Table def k="34mm" dense>

| 仕組み | 内容 |
| --- | --- |
| **反映前の検証** | 品番の重複、必須項目の欠落、数値項目への文字の混入などを検出します。エラーがある場合は**1件も反映しません** |
| **差分の提示** | 「追加3件・更新12件・公開停止1件」のように内容をお示しし、ご確認の操作をもって確定します |
| **削除は公開停止** | 一覧表から行が消えても、データは残したまま非公開にします。誤って消された場合も元に戻せます |
| **履歴と巻き戻し** | 同期前の状態を保持します。反映後に問題が見つかった場合、ひとつ前の状態へ戻せます |
| **項目名での対応付け** | 列は見出しの名前で対応付けます。並べ替えは影響しません。項目名が変わった場合は反映せずお知らせします |

  </Table>

  <Card tone="accent" label="ご安心いただきたい点" title="同期で消えないもの">
  <strong>一覧表の同期対象は、商品情報だけです。</strong>営業ご担当者さまの検討リスト（<Ref ch="7">第7章</Ref>）と利用者アカウントはWebカタログ側で保持するデータですので、同期によって失われることはございません。
  </Card>
</Cols>

</Slide>
