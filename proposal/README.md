# Webカタログ構築のご提案書 — A4横スライドデッキ

Google ドキュメントの提案書を、**A4横のスライドを縦に連ねた印刷対応の1枚もの**として組んだ Astro プロジェクトです。
ブラウザで開いて `Cmd + P` を押すと、そのまま **A4横64ページのPDF** として書き出せます。

---

## 1. すぐに使う

### PDFだけが欲しいとき

`out/Webカタログ構築のご提案書_スタジオスプーン.pdf` をそのままお使いください。

### ブラウザで見て、自分でPDFにするとき

`dist/proposal-deck.html` をダブルクリックしてChromeで開き、`Cmd + P`。
印刷ダイアログで以下を設定してください。

| 設定項目 | 値 |
| --- | --- |
| 用紙サイズ | A4 |
| 向き | 横 |
| 余白 | なし |
| 背景のグラフィック | オン（チェックを入れる） |

`dist/proposal-deck.html` はCSSを内包した単一ファイルなので、そのままメール添付や共有ドライブへの配置もできます。

## 2. テキストを直す

原稿はすべて `src/content/deck/` の中にあります。1ファイル = 1章です。

```
src/content/deck/
├── 00-cover.mdx      表紙
├── 01-agenda.mdx     目次
├── 02-intro.mdx      はじめに
├── 03-summary.mdx    1. 本提案の要点
├── 04-part1.mdx      PART 1 扉
├── 05-ch02.mdx       2. 現状の理解
│   …
└── 27-closing.mdx    巻末（連絡先）
```

中身は **Markdown（MDX）** です。見出し・箇条書き・表は通常のMarkdown記法がそのまま使えます。

```mdx
<Slide chapter="2" chapterTitle="現状の理解" no="2-1" title="紙カタログの制約" lead="リード文">

本文の段落です。**太字**もそのまま効きます。

- 箇条書き
- 箇条書き

| 見出し | 内容 |
| --- | --- |
| 行1 | 値 |

</Slide>
```

- ファイル名の先頭2桁がスライドの並び順です。章を入れ替えたいときは番号を振り直してください。
- スライドを増やすときは `<Slide>...</Slide>` のブロックを複製するだけです。
- ページ番号はCSSカウンターで自動採番されるため、手で振り直す必要はありません。

編集後は次のコマンドで反映します。

```bash
npm run dev      # ブラウザで確認しながら編集（http://localhost:4321）
npm run bundle   # dist/proposal-deck.html を作り直す
```

## 3. 見出しレベルの設計

スライド資料としての可読性を最優先に、5段階で設計しています。

| レベル | 表現 | 使いどころ |
| --- | --- | --- |
| L1 パート扉 | 藍のベタ面＋大きな連番 | 5つの大きなまとまりの切り替わり |
| L2 章 | 各スライド左上の「章番号＋章名」 | 常時表示され、いま何章かが分かる |
| L3 スライド主見出し | `no`（2-1 など）＋ 22ptの見出し＋リード文＋アクセントの短い罫 | スライド1枚のテーマ |
| L4 スライド内小見出し | 左に藍の縦罫が付く13ptの見出し（Markdownの `####` または `<h4>`） | 1枚の中の区切り |
| L5 ラベル | カード左上の小さな大文字ラベル／表のヘッダ | 分類・番号付け |

`no` と `title` を指定するだけで L3 の体裁が整い、`####` を書けば L4 になります。

## 4. デザインを変える

意匠の値は2ファイルに集約しています。

| ファイル | 役割 |
| --- | --- |
| `src/styles/tokens.css` | 色・文字サイズ・余白・用紙寸法などの**デザイントークン**。ここを書き換えると全ページに反映されます |
| `src/styles/deck.css` | トークンを使った実際のレイアウト |

たとえばアクセントカラーを変えるなら `tokens.css` の1行だけです。

```css
--accent: #1f3a5f;   /* ← ここを変えると、罫・番号・カード・パート扉が一斉に変わります */
```

文字を全体的に大きく／小さくしたいときは `--fs-body` などのタイポグラフィ変数を調整してください。

## 5. 使えるコンポーネント

`src/components/` にあります。MDXの先頭でimportして使います。

| コンポーネント | 用途 |
| --- | --- |
| `<Slide>` | 通常のスライド枠。`chapter` `chapterTitle` `no` `title` `lead` `variant` |
| `<Section>` | パート扉（藍ベタ）。`no` `title` `lead` `items` |
| `<Agenda>` | 目次 |
| `<Cover>` / `<Closing>` | 表紙／巻末 |
| `<Cols n={2}>` | 段組み。`2` `3` `4` `"1-2"` `"2-1"` |
| `<Card label title tone>` | カード。`tone` は `plain` `tint` `accent` `mark` |
| `<KeyPoint>` | 要点の帯（左に藍の縦罫＋淡色地） |
| `<Note>` | 補足（上罫＋小さめの文字） |
| `<Steps row>` / `<Step title tag>` | 番号付きの手順。`row` で横並び |
| `<Table def nohead dense center right k="34mm">` | Markdownの表を囲んで体裁を切り替える |
| `<DefRows>` / `<DefRow k="項目">` | 定義リスト（罫線のみの表組み） |
| `<Badge>` | 小さなラベル |

`<Slide variant="center">` を付けると、内容が少ないスライドで本文が版面の縦中央に寄ります。

## 6. 品質チェック

```bash
npm run check
```

全スライドについて、**内容が版面から溢れていないか**と**版面をどれくらい使っているか（fill）**を一覧で出力します。
テキストを増やしたあとは必ず実行してください。溢れがあると `⚠ 溢れ` と表示されます。

```bash
npm run shot 4 12 39     # 指定ページをPNGで書き出す（out/shots/）
node scripts/contact.mjs # 全ページの一覧（コンタクトシート）を書き出す
```

---

## 7. PDFをコマンドで書き出す

```bash
npx playwright install chromium   # 初回のみ
npm run pdf
```

`out/` にA4横のPDFが出力されます。Chromeの印刷ダイアログを使わずに済むので、更新のたびに同じ体裁で出し直せます。

---

## 8. 構成

```
proposal/
├── src/
│   ├── content/deck/     原稿（MDX）— テキスト修正はここだけ
│   ├── components/       スライドの部品
│   ├── layouts/Deck.astro ページの外枠
│   ├── styles/
│   │   ├── tokens.css    デザイントークン
│   │   └── deck.css      レイアウト
│   └── deck.config.ts    タイトル・宛先・日付などのメタ情報
├── scripts/              PDF書き出し・溢れ検査・スクリーンショット
├── source/               元のGoogleドキュメントから取得したMarkdown原文
├── dist/                 ビルド結果（proposal-deck.html が単一ファイル版）
└── out/                  PDF・検証用画像
```

宛先・日付・フッタ文言などは `src/deck.config.ts` にまとめてあります。

---

## 9. 動作環境

- Node.js 20 以上（開発時は v22.22.2 で確認）
- Astro 7 / MDX
- 日本語書体は Noto Sans JP（Google Fonts）を読み込み、オフライン時はヒラギノ角ゴ ProN にフォールバックします
