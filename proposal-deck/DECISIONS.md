## B. 独断で決めた事項

### B-1. フレームワークは Astro（Next.js ではなく）を選択

**理由**

- 印刷用の静的HTMLが最終成果物であり、サーバーやクライアントJSを一切必要としない。Astroは既定でJSをゼロ出力するため、`Cmd + P` の挙動が最も安定する
- MDXが一級市民として扱われ、Markdown原稿の中に `<Slide>` などのコンポーネントをそのまま書ける。Next.jsのApp Routerで同じことをするには MDX 設定の追加配線が必要
- ビルドが1秒未満で、原稿を直しながらの確認が速い

**戻し方**：Next.jsが必須であればお知らせください。コンポーネントとCSSはそのまま移植できます（1〜2時間程度）。

バージョンは Astro 7.2.4（現時点の最新）。動作確認済みです。

### B-2. 原稿は「章ごとに1つの .mdx ファイル」

「Markdownを別ファイルで管理」というご要望に対して、次の3案を検討しました。

| 案 | 内容 | 判断 |
| --- | --- | --- |
| 純粋な .md ＋ レンダラ | 原稿は完全に素のMarkdown | ✅ではない。スライドの区切り・段組み・カードの指定を原稿の外に持つ必要があり、「この文はどのスライドか」が原稿から追えなくなる |
| **章ごとの .mdx** | Markdown本文の中に `<Slide>` などの構造タグだけを置く | **✅ 採用。**本文は素のMarkdownのまま、構造が原稿の中で完結する |
| 1スライド1ファイル | 62ファイルに分割 | ファイル数が多く、章単位の見通しが悪い |

結果、`src/content/deck/` に **28ファイル**（表紙・目次・扉・各章・巻末）を置いています。
テキスト修正はこのフォルダの中だけで完結し、CSSやコンポーネントに触れる必要はありません。

### B-5. 原文の扱い

- **本文の事実・数値・金額表記（◯円 等）は一切変更していません**
- 「御社」→「貴社」への統一など、原文内で表記が揺れていた箇所のみ揃えました（13章・14章）
- 原文の「図1　Webカタログの対象となる範囲」は画像が本文に含まれていなかったため、**図としては再現していません**。第4章の表とカードで内容を表しています。図版をお持ちでしたら差し込みます
- 各スライドのリード文は、原文の導入文をそのまま使うか、原文の内容から要約して書き起こしています。新しい主張は加えていません
- パート扉のリード文、および一部カードの見出し（「制約 01」等のラベル）は新規に作成した文言です

### B-6. デザイン上の決定

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| アクセントカラー | `#1f3a5f`（深い藍） | ミニマル・和文主導のご選択に対し、BtoB製造・卸業界の提案書として最も無難かつ品位が出る色域。`tokens.css` の1行で変更できます |
| 差し色 | `#8c4a2f`（控えめな錆色） | 現在はほぼ未使用。強調が必要になったとき用に用意しています |
| 書体 | Noto Sans JP（Google Fonts）→ ヒラギノ角ゴ ProN にフォールバック | 自己ホスト（fontsource）も検討しましたが、日本語フォント一式で82MBとなりプロジェクトが重くなるため見送りました |
| 本文サイズ | 12pt | 当初9.5ptで組みましたが、版面の使用率が平均50%と間延びしたため段階的に引き上げました。現在の平均使用率は約66%です |
| 版面 | 上14mm／左右20mm／下12mm | A4横で行長が長くなりすぎないよう、本文段落に最大幅（205mm）を設定しています |
| 内容が少ないスライド | 本文を版面の縦中央に寄せる（17枚に適用） | 上詰めのままだと下部が大きく空くため。`variant="center"` で個別に指定しています |

### B-7. PDF出力の方式

- `@page { size: A4 landscape; margin: 0 }` を指定し、スライド1枚 = 1ページに固定
- 丸め誤差による空白ページを防ぐため、印刷時のみスライドの高さを209.9mm（A4横の210mmより0.1mm低い）にしています
- 生成したPDFの用紙寸法は 841.92 × 594.96 pt（実測）。A4横の規格値 841.89 × 595.28 pt との差は最大0.11mmで、印刷実務上は問題ない範囲です
- Chromeの印刷ダイアログから出す場合は「余白：なし」「背景のグラフィック：オン」が必要です（READMEに記載）

### B-8. 品質チェックの仕組みを同梱

`npm run check` で、全64枚について**版面からの溢れ**と**版面の使用率**を自動検査します。
テキストを増やしたときに気づかないうちに文字が切れることを防ぐためのものです。現時点で溢れは0枚です。
