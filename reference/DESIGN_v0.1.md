## 2. 情報設計

### 2-1. サイトマップと URL

```
/                        トップ（ページ数入力を主導線に置く）
/page/{1..77}            誌面ノンブルからの着地ページ
/products                商品一覧（絞り込み・グルーピング・並び替え）
  ?cat={category}          カテゴリー初期選択
  ?band={b1..b5}           容量帯初期選択
  ?q={keyword}             キーワード初期入力
/products/{slug}         商品詳細（SKU単位）
/shortlist               検討リスト
/about                   デモの前提・データ出典・確認事項
```

`slug` は品番を英数字化したもの（例：`YDR-300` → `ydr-300`）。
品番は運用中に変わり得るため、**本番では不変のIDを別に持ち、slug は別項目として管理**することを推奨します
（提案書 2-1 のとおり入れ替えが多いため）。

### 2-2. 導線の優先順位（提案書 8-5）

```
紙カタログを見ているお客さま
        │
        │ 営業担当者さま「◯ページを開いてください」
        ▼
   トップの大きな入力欄  ──── 数字を入力 ────▶  /page/{n}
        │                                          │
        ├─ 品番を入力 ─────────────────────▶ /products/{slug}
        └─ 「調味料」「ダイヤカット」等 ──────▶  /page/{n}（キーワード紐付け）
```

3つの入口を**1つの入力欄に統合**しています。理由は、電話中のお客さまに
「ページ数の欄はこちら、品番の欄はあちら」と選ばせないためです（提案書 9-3）。

## 3. 画面設計

### 3-1. トップ `/`

| 要素 | 意図 |
| --- | --- |
| ページ数入力欄（高さ 64px・文字 24px） | 画面内で最も大きい操作対象。電話中に迷わせない |
| 入力候補のドロップダウン | 数字＝ページ／英数字＝品番／日本語＝誌面カテゴリー名を自動で振り分けて提示 |
| 「よく開かれるページ」チップ（18件） | 数字を打たずに選びたい方向け。誌面色の帯付き |
| カテゴリータイル（4件） | 紙カタログの章立てと同じ区分・同じ色 |
| 容量帯ボタン（5件） | 提案書 8-1 の「その時に必要な分け方」への即アクセス |
| デモの前提の明示 | 実データ／架空データの件数を先に開示する |

**イメージ写真・ブランド訴求要素は置いていません**（提案書 3-2）。

### 3-2. 誌面ページ `/page/{n}`

- ページ番号を大きく表示し、**お客さまが「今どのページを見ているか」を取り違えない**
- そのページの全SKUを1つの比較表に並べる（「その中の◯◯です」の会話に対応）
- 前後ページナビ＋全ページのノンブル一覧（誌面をめくる感覚に合わせる）
- 商品が未登録のページは、その旨を明示（データ収集中であることを隠さない）

### 3-3. 商品一覧 `/products`

| 領域 | PC | スマートフォン |
| --- | --- | --- |
| 絞り込み | 左サイドバー（sticky・常時表示） | ドロワー（件数を出したボタンで確定） |
| 表示形式 | 比較表（既定） / カード | カード（既定） |
| グルーピング | 誌面の項目 / シリーズ / 容量帯 / まとめない | 同じ |
| 並び替え | 誌面の掲載順 / 容量 / 重量 / 全高 / 品番 | 同じ |

**設計上の判断：グルーピングしても表は1つに保つ。**
グループごとに表を分けると列幅がグループ間でずれ、提案書 8-1 の「一覧の段階で仕様の比較ができる」が
成立しません。そのため、`<tbody>` を分けて見出し行を差し込む方式にしています。

### 3-4. 商品詳細 `/products/{slug}`

- 左：図面（タブ切替）
  - 簡易図面（お客さまにも公開）
  - 形状（本番は商品写真に差し替え）
  - **詳細図面（社内モード時のみタブが出現）**
- 右：仕様一覧（14項目）＋機能アイコン＋注釈
- 社内モード時のみ：メーカー情報パネル（オレンジ枠・「お客さまの画面には表示されません」を常時併記）
- 未ログイン時：「メーカー情報と詳細図面は社内用アカウントのみ」の案内を出す
  （**情報が無いのではなく、意図的に隠していること**を営業担当者さまに分かる状態にする）
- 関連商品：同シリーズ／同じ誌面項目、および容量が近い商品

### 3-5. 検討リスト `/shortlist`（提案書 8-6）

- 仕様を縦・候補を横に転置した比較表（横並び比較が目的なので行列を入れ替える）
- 簡易図面のまとめ表示 → `window.print()` で A4 に流し込む（`@media print` で不要要素を除去）
- お客さま名の入力欄（本番では顧客レコードに紐付ける）

## 4. デザインシステム

### 4-1. 選定：Tailwind CSS ＋ shadcn/ui（Radix UI）

| 観点 | 判断 |
| --- | --- |
| メンテナンス性 | コンポーネントがリポジトリ内のコードとして存在する。ライブラリのバージョン差異でUIが勝手に変わらない |
| 表組みの自由度 | 既製のDataGridに乗らない。誌面に合わせた列構成・行高を自前で決められる |
| アクセシビリティ | Radix UI がキーボード操作・フォーカス管理・ARIA属性を担保 |
| 配色変更のコスト | CSS変数の `:root` 1箇所で全画面が変わる |
| 本番移行 | Next.js（静的エクスポート）＝ 提案書 11-2 B案の Vercel 構成とそのまま接続できる |

### 4-2. カラートークン

紙カタログの章タブ色を**実測**してカテゴリー識別色に採用しました（誌面との対応を色で担保するため）。

| カテゴリー | 誌面タブ色（実測） | 文字用（白背景コントラスト比） |
| --- | --- | --- |
| 食品フィルム | `#C48363` | `#AD623E`（4.57:1） |
| 食品プラスチックボトル | `#8FBE86` | `#4E8344`（4.51:1） |
| 食品ガラスボトル | `#89A1C6` | `#5176AE`（4.61:1） |
| 酒類プラスチック・ガラス | `#CFAD5C` | `#907127`（4.59:1） |
| キャップ・その他 | `#A49074` | `#867256`（4.61:1） |

誌面のタブ色はいずれも白背景で 2.1〜3.1:1 しかなく、**そのまま文字色に使うと WCAG AA（4.5:1）を
満たしません。** そのため「帯・面の色」と「文字の色」を別トークンに分け、文字用は明度を落とした
派生色を用意しています。

その他の主要トークン：

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--primary` | `hsl(214 32% 26%)` | ボタン・リンク。カテゴリー色と競合しない濃紺 |
| `--internal` 系 | オレンジ系 4色 | 社内限定情報の識別（誤表示事故の防止） |
| `--row-h` | `2.25rem` | 表の行高。情報密度の基準値 |
| `--radius` | `0.375rem` | 角丸 |

**色は「情報の区別」にだけ使い、装飾には使わない**方針です（提案書 9-1）。

### 4-3. タイポグラフィと情報密度

- 仕様表の文字：13px / 行高 20px（`text-spec`）
- 数値：`font-variant-numeric: tabular-nums`（`.num`）
  → 桁が揃うため、容量・重量・寸法の**縦方向の比較**が目で成立します
- 和文：`font-feature-settings: 'palt'` で約物を詰める
- 狭い画面の横スクロール表には、端が続いていることを示すグラデーション（`.scroll-x`）

### 4-4. コンポーネント一覧

```
src/components/ui/     shadcn/ui 準拠のプリミティブ
  button / badge / input / checkbox / switch / separator
  dialog / sheet / tabs / accordion / tooltip / toggle-group / select-native
src/components/        ドメイン固有
  site-header          ヘッダー（統合検索・社内モード・検討リスト）
  catalog-search       ページ数／品番／キーワードの統合検索
  filter-panel         絞り込み（ファセット件数付き）
  product-table        比較表（グループ見出し行つき・1テーブル）
  product-card         カード表示
  container-drawing    シルエット／簡易図面／詳細図面（SVG）
  bits                 カテゴリーバッジ・社内限定枠・注記など小物
```

並び替えは**OSネイティブの `<select>`** を採用しています。独自ドロップダウンより、
スマートフォンでの操作性とスクリーンリーダー互換を優先する判断です。

### 5-1. リサイクルマーク刻印について（要対応）

提案書 2-2 で「**単なる属性情報ではなく商品選定の必須条件**」と位置づけた項目ですが、
現行の仕様リストには**独立した列が存在しません。** 注釈欄の `※PETマーク` `※PETマーク品あり` から
判定できるのは 263SKU 中 4件のみで、残りは `要確認` になります。

- デモでは「要確認」として正直に表示し、絞り込み条件にも `要確認` を選択肢として出しています
- **本番では専用の列を新設し、データ再収集（提案書 14-1／2026年9〜10月）の照会項目に含めること**を
  お客さまに提案する必要があります
- 中身（醤油＝マーク有／油＝マーク無）で選べる容器が決まる以上、この列が無いと
  提案書 8-1 で約束した絞り込みが成立しません

これは 8/21 のご説明でお伝えするべき事項です。

### 5-2. 誌面ノンブルとの対応

| 対象 | 導出方法 | 確度 |
| --- | --- | --- |
| 仕入れ品（調味料） | 容量から誌面のページ範囲へ割り当て（100〜280→29、300〜360→30、400〜870→31、1,000〜1,800→32） | high |
| 仕入れ品（広口・粉末） | 項目 → 33 | high |
| 仕入れ品（密封ボトル） | 項目 → 36 | high |
| 仕入れ品（飲料） | 材質で PET → 37 / PP・PE → 38 | high |
| 仕入れ品（単層・多層・チューブ） | 項目 → 34・35 | medium（2ページのどちらかを特定できない） |
| 自社オリジナル | **確定できず** | unresolved |

自社オリジナル（28SKU）については、シートに誌面ページの情報が無く、
誌面 24〜27ページ（Cシリーズ／FY&AYシリーズ／小容量／その他）との対応が推測になるため、
**空欄のまま「要確認」表示**にしています。あわせて提案書 4-1 では
「貴社オリジナルのドレッシング用ペットボトルを除く」とあり、そもそも移行対象外の可能性があります。
→ **8/21 の読み合わせで確認する項目**です。

## 6. 主要機能の実装方針

### 6-1. 検索（`src/lib/catalog.ts`）

```
入力 → 正規化（NFKC・小文字化・記号除去）
      ├ 1〜3桁の数字かつ 1〜77 → 誌面ページとして最優先で候補に出す
      ├ 品番の前方一致 → 部分一致（この順で並べる）
      └ 誌面カテゴリー名・通称（22語を紐付け）
```

キーワード辞書（「調味料」「ダイヤカット」「ジャム」「ワイン」など22語）は
提案書 8-5 の「カタログ内のカテゴリー名からも同じページに到達できるようにする」に対応します。

### 6-2. 絞り込み（`src/lib/filters.ts`）

- **ファセットの件数は、他の条件を適用した結果から動的に算出**しています
  → 「押しても0件」の選択肢を出さない（提案書 9-3 の「押せる箇所が押せると分かる」の裏返し）
- 条件は URL クエリで初期化できるため、営業担当者さまが特定の絞り込み状態を
  お客さまに共有することも将来的に可能です

### 6-3. 図面の生成（`src/lib/geometry.ts` / `src/components/container-drawing.tsx`）

SKU単体の写真・図面が未支給のため、仕様値から SVG を描画しています。

```
胴サイズ（Φ66 / 116×116（角）/ 97（六角）/ W60×D48（楕円））
  → 形状 と 幅・奥行
全高 ＋ 胴幅 → 縦長ボトル（H ≧ W×1.35）か 平たい容器（ジャー）かを判定
口部表記 → 口部呼び径（26.3樹脂王冠 → φ26.3、アルコア口 → φ28 等。読めない場合は寸法を出さない）
ラベル面 → 破線の帯として描画
```

**数値として書き込むのは、マスターに実在する項目だけに限定しています。**
肩の位置・板厚・首の高さは描画のために比率で補っていますが、寸法線としては出しません
（もっともらしい数字を図面に載せると、そのまま社内に流通してしまうため）。

| 図面 | 公開範囲 | 内容 |
| --- | --- | --- |
| 形状（シルエット） | お客さま | 寸法なし。本番は商品写真に差し替え |
| 簡易図面 | お客さま | 胴サイズ・全高・ラベル面・容量 |
| 詳細図面 | **社内のみ** | 上記＋口部呼び径・上面図・図枠・表題欄（メーカー名入り） |

### 6-4. 画像・図面のファイル名規則（提案書 10-2 の設計）

本番では以下を想定しています（デモには実装していません）。

```
{品番}_photo.jpg      商品写真
{品番}_simple.svg     簡易図面（お客さまに公開）
{品番}_detail.pdf     詳細図面（社内のみ）
```

- CSVには長いパスではなく**ファイル名のみ**を書く（提案書 10-2）
- 品番に含まれる空白・全角記号はファイル名側で `_` に置換する規則が必要
  （例：`M-PET 280F` → `M-PET_280F_photo.jpg`）
  → **この置換規則は運用開始前に文書化しておくこと**

### 6-5. 社内モード（提案書 8-3 / 8-4）

| 設計 | 理由 |
| --- | --- |
| 既定は必ず OFF | 未ログイン状態が「お客さまに見せて安全な状態」であるべき |
| 状態はメモリ上のみ（ブラウザに保存しない） | タブを閉じれば必ず OFF に戻る。誤表示事故を実装で防ぐ |
| 共通パスコード1本（個別アカウントを発行しない） | アカウントが増えるほど管理負荷が増える、というご懸念への対応 |
| ON のときヘッダーがオレンジに変わる | 画面共有中に「今は社内モードだ」と一目で分かる |
| 詳細図面はタブ自体が出現／消滅する | 押せるのに見えない、という状態を作らない |

デモのパスコードは `yamato` です。
**本番では認証をサーバー側で行い、セッション管理・SSL・管理画面のアクセス制限を実装します**
（提案書 11-3）。フロントエンドだけの判定は、デモとしての挙動再現に限られます。

## 9. データ変換で検出した確認事項（11件）

`src/data/dataset.json` の `issues` に格納し、`/about` 画面にも表示しています。

1. **`M-PET 200M-VR` の容量が `=EXACT`**
   Excel の数式エラーが値として保存されています。原本の修正が必要です。
   デモでは推測で 200 を埋めず、空欄扱いにしています。
2. **自社オリジナル 10SKU の誌面ページが不明**
   `YD-S-100` `YDR-T-150` `YDR-S-170` `YDR-ST-200` `YDR-N-200` `YDR-G-300`
   `YDR-T-200` `YDR-300` `YD-K-130` `YD-K-200`
   （ダイヤカットシリーズ／YDRシリーズ／Kシリーズ）

そのほか、変換時に確認した事項：

- `重量` に `18・23` のような複数値、`入数` に `3,456/PL` `未定` が混在
  → 数値と表示用文字列を分けて保持（絞り込みは数値、表示は原文）
- `耐熱温度` の `-` は「該当なし」なのか「未確認」なのか区別できない
  → 数値化せず `—` と表示。**再収集時に区別できる記入ルールを決めることを推奨**
- 「変更箇所」「廃盤・変更」列に運用メモ（`容量・サイズ修正要` `キャップ名修正` 等）が10件以上
  → 本番の管理画面では更新履歴として別項目に分離すべき
